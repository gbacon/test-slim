# Current design

`Test::Slim` has three small execution layers. `Test::Slim::Server` reads and writes framed SLiM messages over a socket. `Test::Slim::List` handles SLiM list values and lengths, including recursive nested statements and zero-length string items. `Test::Slim::ListExecutor` turns each decoded statement into a `Test::Slim::Statement` call.

`Test::Slim::Statement` routes protocol operations to `Test::Slim::StatementExecutor`. The statement executor owns imported class prefixes, actor instances, registered library instances, and symbols. It resolves graceful class and method names, constructs fixtures, substitutes symbols, converts HTML table arguments where appropriate, dispatches actor methods first, then an optional System Under Test, then registered libraries newest-first, and formats results or SLiM exceptions. A Perl fixture declares its SUT in a blessed-hash field named `system_under_test` (or Java-compatible `systemUnderTest`); missing actor methods are called on that object before library lookup. Actor methods retain precedence, and an exception raised by the SUT is returned without retrying a library method. Each executor also creates a private automatic `SlimHelperLibrary`, registered as the oldest library. Its `get_fixture`, `push_fixture`, and `pop_fixture` methods read, save, and restore the exact `scriptTableActor` reference; a missing actor raises the upstream `NO_INSTANCE` error. Explicitly registered libraries remain newer, and each executor owns an isolated LIFO actor stack. A call to FitNesse's `cloneSymbol` helper uses the reserved `null` target and returns the resolved symbol value unchanged, preserving object identity. If a scenario call names an actor that has no instance, dispatch searches registered libraries newest-first before reporting an error.

Perl tests use fixtures under `t/lib/`. The `Eg::Division` fixture mirrors FitNesse's `eg.Division` example: it stores numerator and denominator state, exposes setters, and returns a Java-compatible double quotient. `Fitnesse::Slim::Test::ShouldIBuyMilk` mirrors the upstream decision-table fixture, including its stateful milk/cash/card decision and optional no-op table hooks. The acceptance `TestSlim` fixture provides its upstream `toString()` value through Perl stringification while keeping `==` and `is_same` based on reference identity. FitNesse acceptance pages live in the locally installed wiki tree (ignored by Git) and connect through the Perl server on port 8099. The acceptance inventory and the current observed failure groups are recorded in [`docs/fitnesse-slim-acceptance-baseline.md`](docs/fitnesse-slim-acceptance-baseline.md).

`PageDriver` and `ResponseExaminer` are acceptance-test harness fixtures, not protocol components. Upstream PageDriver creates pages and runs FitNesse requests using FitNesse's in-process wiki/request context; ResponseExaminer reads the resulting response and page HTML from that context. The Perl PageDriver in `t/lib/Fitnesse/Fixtures/PageDriver.pm` makes the equivalent FitNesse `saveData` and `saveProperties` requests over HTTP, runs page/test/suite/log responders, and retains each response's status and body. Its acceptance-used `content`, `contentContains`, `contentMatches`, and `lineNumberContaining` methods inspect that body. `Fitnesse::Fixtures::ResponseContext` exposes the most recent HTTP response to other harness fixtures in the same worker process. `ResponseExaminer` in `t/lib/Fitnesse/Fixtures/ResponseExaminer.pm` reads this shared status and body, supports the upstream `contents`, `rawContents`, `fullContents`, `pageContents`, `pageHtml`, and `status` selectors, and performs Java-style multiline/dotall regex extraction through `found` and `extractMatch`. It also exposes the upstream line and match-count helpers needed by fixtures; it introduces no HTTP client or protocol state.

The same boundary limits `CustomTableRenderingAddedByPluginTest`. The upstream suite `SetUp` registers `CustomTableAliasPlugin` and `CustomScriptTableRenderingPlugin` in the test context. The installed plugin classes register aliases through `SlimTableFactory.addAlias`; the rendering plugin also installs a parsed-symbol decorator that adds `myUseCase` to script-table markup. Upstream Java PageDriver issues nested requests in its current configured context, while the Perl HTTP PageDriver requests the generated page from the main server. The nested page therefore lacks both the `my use case` alias and the decorator. Two direct runs each report 5 right and 1 wrong: the failed outer assertion expects `table class="myUseCase"` in the nested response, where that markup is absent. FitNesse reports `Could not find class MyUseCase` (and `MyFixture` in the second, negative-control page). The fixture return value and SLiM protocol are not responsible for the missing CSS class; ResponseExaminer simply inspects the returned HTTP body. This is another configured-context harness limitation, not a Perl compatibility defect. Supporting it correctly requires a context-aware nested-page harness; do not inject these plugin behaviors globally or page-specifically.

The HTTP PageDriver does not share FitNesse's in-process `FitnesseFixtureContext`. This matters for `TestCustomComparators`: the upstream suite `SetUp` constructor creates the context with `CustomComparators=glob:fitnesse.testsystems.slim.GlobComparator`, and the upstream Java PageDriver runs generated `TestPage` requests in that context. The Perl PageDriver instead requests the generated page from the main server, whose comparator registry does not include `glob`. Both nested checks consequently compare actual `test` to literal expected `glob:t*t` and fail, even though `EchoFixture` and the Perl SLiM response are correct. Preserving configured contexts for nested requests requires a broader harness boundary than the current HTTP response adapter. Do not add page-specific or global comparator registration as a workaround; the next viable increment is a context-aware nested-page harness that exercises the existing `SetUp` configuration path.

Generated pages used by the acceptance `PageDriver` are stored in FitNesse's wiki across HTTP requests. Several upstream stop tests reuse the name `MySuite`; `StopTestInSuiteSetUp` leaves a `MySuite.SuiteSetUp` page behind, which can change later StopTest and StopSuite results. The acceptance inventory runner clears that generated suite with FitNesse's `deletePage` responder before each page request. This isolates page-level conformance checks without changing upstream pages or SLiM stop handling.

The test fixtures `Fitnesse::Fixtures::SplitFixture` and `Fitnesse::Fixtures::DuplicateRows` mirror the installed FitNesse v20251025 query fixtures. Both take one string constructor argument and expose `query()`, returning nested row lists whose entries are column/value pairs. SplitFixture splits semicolon-separated rows and comma-separated cells and labels columns with one-based string keys. DuplicateRows returns the upstream phase A/B order and retains duplicate values. The query tests also use the protocol 0.4 `assign` instruction, which stores a symbol value (including null) and returns `OK`; the server advertises `Slim -- V0.4` accordingly. These fixture implementations remain under `t/lib/Fitnesse/Fixtures/`, outside the core executor.

`Fitnesse::Slim::Test::AddUpChange` mirrors the installed `fitnesse.slim.test.AddUpChange` fixture. Each actor owns an integer cents total; `set(coin, amount)` adds one of six supported denominations, `get("$ total")` formats dollars to two decimal places, other `get` values return cents, and `reset()` clears the total. Unknown coin names produce the upstream `IllegalArgumentException` message. It is a regular fixture under `t/lib`, so aliases and hybrid decision-table method extraction continue through the existing executor.

`Fitnesse::Slim::Test::Library::LibraryInSetUp` mirrors the upstream setup-library fixture: `echo()` records a call on that library instance, and `echoInSetUpLibraryCalled()` reports its state as a SLiM boolean string. `LibraryFixture` remains empty, so a missing actor method is supplied through normal library lookup. Library registry entries retain object references alongside their FitNesse names. Reused names therefore do not overwrite earlier objects; direct lookup uses the first matching registration, while method fallback searches newest-first, matching upstream `SlimExecutionContext` and `LibraryMethodExecutor`.

The `Fitnesse::Fixtures::EchoFixture` test fixture stores its optional name, exposes `set_name`, `name`, and `name_contains`, and supports the upstream echo, integer echo, and echo-and-log methods. `Fitnesse::Fixtures::HashFixture` accepts the converted input map, returns its map for HTML rendering, and exposes `hash_is` with the upstream log line and stored value. These methods remain test fixtures, not protocol conversions; the existing map-result converter and table-to-hash argument handling are unchanged.

`Fitnesse::Slim::Test::Sleep` mirrors the installed upstream timeout fixture. It has a zero-millisecond default timer, accepts an optional constructor delay, stores timer values in milliseconds, sleeps for the selected duration, and returns `WakeUp <milliseconds>`. Negative durations raise Java's `IllegalArgumentException` message. The fixture uses Perl's core `Time::HiRes`; FitNesse timeout enforcement remains a runner concern, separate from sleeping in a fixture method.

`Fitnesse::Slim::Test::EchoScript` reproduces the upstream echo, stdout, and stderr methods. Standard output is written as UTF-8 bytes so Unicode fixture values are logged without Perl wide-character warnings; all three methods return the original Perl value so SLiM's Unicode serialization remains independent from log encoding.

`Fitnesse::Slim::Test::TestSlim::concatenate_three_args` joins its three script arguments with spaces, matching the upstream fixture used to exercise FitNesse's sequential-argument table syntax. Argument grouping remains FitNesse's responsibility; the fixture receives the resolved method arguments as usual.

`Fitnesse::Slim::Test::LoginDialogDriver` stores the expected username and password, counts every login attempt, and retains the upstream success/failure message. It returns SLiM boolean strings for accepted and rejected credentials.

`Fitnesse::Slim::Test::DetailedDiff` stores actual string, integer, double, and symbol values through the upstream setters, returns each through its matching `expected*` getter, and echoes a string. Its nested acceptance page uses FitNesse's own comparator and HTML diff rendering; the Perl fixture only supplies the state and values.

Fixtures implementing the upstream `StatementExecutorConsumer` contract receive their active executor through `set_statement_executor` after construction. They can set the reserved `SLIM_AGENT_FIXTURE_HANDLES_SYMBOLS` symbol to a regex of `instance.method` calls; only matching calls bypass ordinary symbol substitution. Setting the reserved symbol to null restores normal replacement. This is required for table fixtures that read and assign symbols inside one table, while keeping regular fixture calls unchanged.

`Fitnesse::Slim::Test::Statementexecutorconsumer::TableTableIncFirstCol` uses that hook to read symbol values in each input row, increment the first value, assign the result to the symbol named in the second cell, and return the upstream two-column result rows. It clears fixture-managed symbol mode even when a row fails. The acceptance page also checks symbol assignments before and after the table through the ordinary executor path.

`Test::Slim::ConverterRegistry` provides the small conversion contract needed by typed fixtures. Fixtures may expose `slim_method_signature($method)` with declared parameter and return type names; this explicit metadata avoids Java-style reflection and leaves unannotated fixture dispatch unchanged. Each `StatementExecutor` owns a registry, so converter changes are isolated to that SLiM connection. Arguments already supplied as references and null arguments pass through unchanged; scalar arguments use the declared type's `from_string` converter. Results use the declared converter, then the runtime-class converter as fallback. An exact `java.util.List` return that is already an array reference remains a nested SLiM list, while collection implementations such as `java.util.ArrayList` use the registered List converter. Collection elements are rendered recursively through runtime converters, and opaque references without a converter or explicit string method raise an exception instead of leaking a Perl address. Converter failures become SLiM exceptions with the invocation name. Standard String, boxed/primitive Boolean, Integer, Long, Double, void, and List converters are installed on reset. Numeric blank handling follows FitNesse: boxed numeric values become null, primitive numeric values become zero; Integer and Long enforce Java signed bounds. Double accepts decimal and exponent syntax. Java's Date and Character converters, Java-specific non-decimal Double forms, dynamically inferred enum/array/collection converters, and JavaBeans property editors remain unsupported as implicit defaults. Fixtures can register, restore, or reset converters for those additional types.

`Fitnesse::Slim::Test::TestSlimWithConverter` mirrors upstream `TestSlimWithConverter`: its custom List converter changes collection string results from square to curly brackets and accepts both forms as a List argument. Its exact `List` getter continues to produce a nested SLiM list. Focused coverage is in `t/custom-converters.t`; the unchanged upstream `TestCustomConverter` page validates the observable dispatch and result behavior.

Fixture exceptions are formatted at the statement executor boundary. Ordinary fixture exceptions become SLiM exception results, preserving Java-style class names and messages where fixtures provide them. `ConstructorThrows` and `DecisionTableExecuteThrows` reproduce the upstream acceptance fixtures. Stop-test and stop-suite exceptions carry FitNesse's `ABORT_SLIM_TEST` or `ABORT_SLIM_SUITE` marker; `ListExecutor` then omits the remaining statements in that instruction batch and clears the stop request before the next batch. FitNesse consequently decides which later pages and teardown steps to run, while the Perl executor keeps ordinary exceptions non-stopping. These semantics are covered in `t/stop-exceptions.t` and the `StopSuite`, `StopTest`, and `StopTestInSuiteSetUp` acceptance pages.

`IgnoredTestsShouldColorGray` also verifies that a StopTest exception prevents later script calls and marks them ignored. Those semantics pass. Its two remaining outer checks expect `class="ignore">Not Executed and should be ignored<` and `class="ignore">Not Executed and should be ignored as well<`. FitNesse v20251025 instead renders `<tr class="slimRowColor3"><td>Not Executed and should be ignored <span class="ignore">Test not run</span></td></tr>` and the corresponding second row with `slimRowColor5`. The installed `SlimTable.RowExpectation` marks missing results as not run, while `HtmlTable.Cell` renders a non-counting ignore as the original content plus `<span class="ignore">Test not run</span>`; the row color class is attached to `<tr>`. ResponseExaminer exposes the response content used by the page check without changing the markup. These are obsolete HTML expectations, not Perl stop or ignore defects. The upstream-compatible remedy is to update the two acceptance checks to assert the current ignore result span/status; do not emulate the old HTML shape in Perl or ResponseExaminer.

The two `ErrorSituationsDuringSlimServerStartup` pages cannot exercise their intended startup failures through the shared acceptance harness configuration. `B_TimeoutAsSlimServerDiesBeforeConnecting` creates a nested page with an invalid `TEST_RUNNER` and expects FitNesse to report `Error SLiM server died before a connection could be established.` The active FitNesse process has `manually.start.test.runner=true`, so the nested request skips launching that runner and connects to the already-running Perl `SlimService` on 127.0.0.1:8099; its log reports `Connection to running SlimService`, exit 0, and zero seconds. `C_TimeoutAsNoServerAtGivenSocket` expects connection refusal at port 8099, but the external Perl service occupies that port, so its nested debug request also connects successfully. Both pages were run twice with identical outcomes: B has 2 right/1 wrong and C has 3 right/1 wrong; only each expected-error-text check fails. Their HTTP status and execution-log checks pass. These pages use PageDriver's nested HTTP requests and body checks directly; ResponseExaminer is not involved. The responsibility is shared harness/environment configuration, not Perl SLiM protocol behavior. A faithful run needs an isolated FitNesse context: run the outer suite against Perl on an alternate port, leave 8099 unbound for C, and allow B's nested request to use normal child-runner startup with its deliberately invalid runner. This requires independent startup properties and service ports; do not fake errors or alter page expectations to make the shared-server run pass.

Method results that are plain Perl hash references are converted at the statement-executor boundary by `Test::Slim::MapResult`, matching FitNesse's MapConverter HTML table representation. It sorts map keys for stable output, escapes ordinary cell text, retains valid HTML, and handles nulls and nested arrays/maps. This conversion is limited to map results; array references remain nested SLiM lists and other object references are not globally stringified. Object values inside a map require an explicit Perl string method, so opaque references cannot leak as `HASH(0x...)`. The behavior and identity preservation are covered by `t/hash-results.t`.

The wire implementation accepts six-or-more-digit SLiM 0.4 length fields. `Server::_read_message` reads the colon-terminated byte-length prefix independently of its digit count and bounds it to Java's signed integer range; list string lengths are UTF-16 code units. The list parser indexes through decoded Unicode instead of repeatedly deleting leading characters. Regression tests cover a 1,000,000-unit list string, a 1,000,000-byte frame, multibyte and supplementary Unicode, and the byte/unit distinction. Fixture result conversion is declared explicitly through `slim_method_signature`: the standard registry emits FitNesse's `/__VOID__/` for declared void methods and lowercase text for boxed Boolean results. Undefined results from `callAndAssign` remain undefined in the executor's symbol store even though the wire response serializes them as `null`; exact symbol references preserve that value, while embedded null symbols interpolate as `null` text. A fixture exception does not bind a `callAndAssign` result. Ignore exceptions produce FitNesse's exact marker and stop the current instruction batch; the stop flag resets after that batch, leaving script/test scope filtering to FitNesse. Library instance names follow the protocol's `library` prefix, without requiring a numeric suffix. The conformance matrix in [`docs/slim-protocol-conformance.md`](docs/slim-protocol-conformance.md) records verified behavior and unsupported areas, including Java annotation discovery for arbitrary SUT fields, v0.5 stdin/stdout transport, and general Java converter coverage.

A nested `?test` starts another FitNesse-to-SLiM connection while the outer PageDriver call waits, so `Test::Slim::Server` accepts clients in the parent and forks one worker per connection. Each `process` call gets a fresh `ListExecutor`, which owns the session's actors, symbols, libraries, fixture instances, imports, and response context. The parent closes its copy of each accepted socket and reaps worker processes on `SIGCHLD`; a malformed or disconnected client closes only its worker's socket. This server model requires Perl `fork` support, which is available in the current Linux Codespaces and CI environments. Keep the HTTP client and response extraction in `t/lib/Fitnesse/Fixtures/`, outside `lib/Test/Slim/`.

# FitNesse acceptance runner

`bin/test-fitnesse` is the supported local and CI entry point for the 50-page upstream SLiM inventory. It keeps test harness concerns outside the SLiM engine: `Test::Slim::FitNesseAcceptance` parses FitNesse XML, compares observed page conformance with the committed JSON inventory, checks required Test=true wiki pages, and probes the SLiM greeting. The command owns only processes it starts, uses bounded readiness and request timeouts, clears generated `MySuite` pages before each request, and requires each execution log to identify the external `fitnesse.slim.SlimService` connection and its configured Perl listener. Its `END` cleanup terminates and reaps owned processes while restoring the runner's prior exit status, so a child's intentional `SIGTERM` cannot replace either a successful result or an existing failure status. Known non-conformant baseline pages are reported without failing the run; a regression, missing/unexecuted page, service mismatch, or server exit fails it. CI runs `bin/test-dev` and this runner in the same container built by the existing workflow.
