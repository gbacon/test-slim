# Current design

`Test::Slim` has three small execution layers. `Test::Slim::Server` reads and writes framed SLiM messages over either a TCP socket or inherited stdin/stdout pipes. Both transports use the same session loop, framing, deserialization, and executor. TCP retains the v0.4 greeting; port `1` selects the v0.5 pipe session. Pipe mode keeps a duplicate of stdout for protocol bytes, redirects otherwise-unscoped stdout away from that descriptor, and captures fixture stdout and stderr separately while each instruction executes. The capture files are disk-backed and read in bounded chunks, then converted to FitNesse's v0.5 diagnostic records on the child's stderr. `Test::Slim::List` handles SLiM list values and lengths, including recursive nested statements and zero-length string items. `Test::Slim::ListExecutor` turns each decoded statement into a `Test::Slim::Statement` call and can invoke a small post-statement hook without changing stop/ignore batch behavior.

`Test::Slim::Statement` routes protocol operations to `Test::Slim::StatementExecutor`. The statement executor owns imported class prefixes, actor instances, registered library instances, and symbols. It resolves graceful class and method names, constructs fixtures, substitutes symbols, converts HTML table arguments where appropriate, dispatches actor methods first, then an optional System Under Test, then registered libraries newest-first, and formats results or SLiM exceptions. For fixture class lookup, a more-specific imported package takes precedence over its parent; later imports are tried first among equally specific packages. A Perl fixture declares its SUT in a blessed-hash field named `system_under_test` (or Java-compatible `systemUnderTest`); missing actor methods are called on that object before library lookup. Actor methods retain precedence, and an exception raised by the SUT is returned without retrying a library method. Each executor also creates a private automatic `SlimHelperLibrary`, registered as the oldest library. Its `get_fixture`, `push_fixture`, and `pop_fixture` methods read, save, and restore the exact `scriptTableActor` reference; a missing actor raises the upstream `NO_INSTANCE` error. Explicitly registered libraries remain newer, and each executor owns an isolated LIFO actor stack. A call to FitNesse's `cloneSymbol` helper uses the reserved `null` target and returns the resolved symbol value unchanged, preserving object identity. If a scenario call names an actor that has no instance, dispatch searches registered libraries newest-first before reporting an error.

Perl tests use fixtures under `t/lib/`. The `Eg::Division` fixture mirrors FitNesse's `eg.Division` example: it stores numerator and denominator state, exposes setters, and returns a Java-compatible double quotient. `Fitnesse::Slim::Test::ShouldIBuyMilk` mirrors the upstream decision-table fixture, including its stateful milk/cash/card decision and optional no-op table hooks. The acceptance `TestSlim` fixture provides its upstream `toString()` value through Perl stringification while keeping `==` and `is_same` based on reference identity. FitNesse acceptance pages live in the locally installed wiki tree (ignored by Git) and connect through the Perl server on port 8099. The acceptance inventory and the current observed failure groups are recorded in [`docs/fitnesse-slim-acceptance-baseline.md`](docs/fitnesse-slim-acceptance-baseline.md).

`PageDriver` and `ResponseExaminer` are acceptance-test harness fixtures, not protocol components. Upstream PageDriver creates pages and runs FitNesse requests using FitNesse's in-process wiki/request context; ResponseExaminer reads the resulting response and page HTML from that context. The Perl PageDriver in `t/lib/Fitnesse/Fixtures/PageDriver.pm` makes the equivalent FitNesse `saveData` and `saveProperties` requests over HTTP, runs page/test/suite/log responders, and retains each response's status and body. Its acceptance-used `content`, `contentContains`, `contentMatches`, and `lineNumberContaining` methods inspect that body. `Fitnesse::Fixtures::ResponseContext` exposes the most recent HTTP response to other harness fixtures in the same worker process. `ResponseExaminer` in `t/lib/Fitnesse/Fixtures/ResponseExaminer.pm` reads this shared status and body, supports the upstream `contents`, `rawContents`, `fullContents`, `pageContents`, `pageHtml`, and `status` selectors, and performs Java-style multiline/dotall regex extraction through `found` and `extractMatch`. It also exposes the upstream line and match-count helpers needed by fixtures; it introduces no HTTP client or protocol state.

The same boundary limits `CustomTableRenderingAddedByPluginTest`. The upstream suite `SetUp` registers `CustomTableAliasPlugin` and `CustomScriptTableRenderingPlugin` in the test context. The plugins register the alias through `SlimTableFactory.addAlias` and decorate script-table markup with `myUseCase`. The Perl HTTP PageDriver requests its generated page from the main server, not the active FitNesse test context, so the alias and decorator are absent. Perl reports 5 right and 1 wrong; its nested response says `Could not find class MyUseCase`, and the negative-control page reports `MyFixture`. The Java reference run on the pinned JAR reports 6 right and 0 wrong, logs plugin registration, and includes `<table class="myUseCase">`. This is a FitNesse nested-context harness limitation, not a fixture return or SLiM protocol defect. The comparator page has the same context boundary. See [`docs/fitnesse-rendering-comparator-compatibility.md`](docs/fitnesse-rendering-comparator-compatibility.md) for all five assertion comparisons.

The HTTP PageDriver does not share FitNesse's in-process `FitnesseFixtureContext`. This matters for `TestCustomComparators`: the upstream suite `SetUp` constructor creates the context with `CustomComparators=glob:fitnesse.testsystems.slim.GlobComparator`, and the upstream Java PageDriver runs generated `TestPage` requests in that context. The Perl PageDriver instead requests the generated page from the main server, whose comparator registry does not include `glob`. Both nested checks consequently compare actual `test` to literal expected `glob:t*t` and fail, even though `EchoFixture` and the Perl SLiM response are correct. Preserving configured contexts for nested requests requires a broader harness boundary than the current HTTP response adapter. Do not add page-specific or global comparator registration as a workaround; the next viable increment is a context-aware nested-page harness that exercises the existing `SetUp` configuration path.

Generated pages used by the acceptance `PageDriver` are stored in FitNesse's wiki across HTTP requests. Several upstream stop tests reuse the name `MySuite`; `StopTestInSuiteSetUp` leaves a `MySuite.SuiteSetUp` page behind, which can change later StopTest and StopSuite results. The acceptance inventory runner clears that generated suite with FitNesse's `deletePage` responder before each page request. This isolates page-level conformance checks without changing upstream pages or SLiM stop handling.

The test fixtures `Fitnesse::Fixtures::SplitFixture` and `Fitnesse::Fixtures::DuplicateRows` mirror the installed FitNesse v20251025 query fixtures. Both take one string constructor argument and expose `query()`, returning nested row lists whose entries are column/value pairs. SplitFixture splits semicolon-separated rows and comma-separated cells and labels columns with one-based string keys. DuplicateRows returns the upstream phase A/B order and retains duplicate values. The query tests also use the SLiM `assign` instruction, which stores a symbol value (including null) and returns `OK`. The server advertises `Slim -- V0.5` over TCP and port-1 pipes for the pinned FitNesse release. These fixture implementations remain under `t/lib/Fitnesse/Fixtures/`, outside the core executor.

Perl symbol substitution handles protocol symbol references such as `$NAME`, including exact reference-preserving substitution and embedded text replacement. It does not evaluate FitNesse's ``$`expression` `` table syntax. FitNesse v20251025's Java `VariableStore` and `SlimTable` use Nashorn through `SlimExpressionEvaluator`, converting serialized map/list values to Java objects before evaluating JavaScript and Java methods. This documented FitNesse table feature is outside the SLiM protocol's five instruction forms and named-symbol substitution rules. The Perl executor leaves these expressions as ordinary text; this is a known compatibility boundary, not a protocol implementation defect. Do not add general `eval` to the core executor. Any future expression support must be a separately scoped, explicitly enabled component with a defined grammar and conversion/error contract. See [`docs/slim-symbol-expression-compatibility.md`](docs/slim-symbol-expression-compatibility.md) for the page-level comparison and evidence.

`Fitnesse::Slim::Test::AddUpChange` mirrors the installed `fitnesse.slim.test.AddUpChange` fixture. Each actor owns an integer cents total; `set(coin, amount)` adds one of six supported denominations, `get("$ total")` formats dollars to two decimal places, other `get` values return cents, and `reset()` clears the total. Unknown coin names produce the upstream `IllegalArgumentException` message. It is a regular fixture under `t/lib`, so aliases and hybrid decision-table method extraction continue through the existing executor.

`Fitnesse::Slim::Test::Library::LibraryInSetUp` mirrors the upstream setup-library fixture: `echo()` records a call on that library instance, and `echoInSetUpLibraryCalled()` reports its state as a SLiM boolean string. `LibraryFixture` remains empty, so a missing actor method is supplied through normal library lookup. Library registry entries retain object references alongside their FitNesse names. Reused names therefore do not overwrite earlier objects; direct lookup uses the first matching registration, while method fallback searches newest-first, matching upstream `SlimExecutionContext` and `LibraryMethodExecutor`.

The `Fitnesse::Fixtures::EchoFixture` test fixture stores its optional name, exposes `set_name`, `name`, and `name_contains`, and supports the upstream echo, integer echo, and echo-and-log methods. `Fitnesse::Fixtures::HashFixture` accepts the converted input map, returns its map for HTML rendering, and exposes `hash_is` with the upstream log line and stored value. These methods remain test fixtures, not protocol conversions; the existing map-result converter and table-to-hash argument handling are unchanged.

`Fitnesse::Slim::Test::Sleep` mirrors the installed upstream timeout fixture. It has a zero-millisecond default timer, accepts an optional constructor delay, stores timer values in milliseconds, sleeps for the selected duration, and returns `WakeUp <milliseconds>`. Negative durations raise Java's `IllegalArgumentException` message. The fixture uses Perl's core `Time::HiRes`; FitNesse timeout enforcement remains a runner concern, separate from sleeping in a fixture method.

`Fitnesse::Slim::Test::EchoScript` reproduces the upstream echo, stdout, and stderr methods. Standard output is written as UTF-8 bytes so Unicode fixture values are logged without Perl wide-character warnings; all three methods return the original Perl value so SLiM's Unicode serialization remains independent from log encoding.

Pipe-mode output is kept out of the protocol descriptor even when fixtures use bare or explicit Perl `print`, low-level writes to file descriptors 1 and 2, or synchronous child processes that inherit them. After each SLiM instruction, the server forwards captured stdout as `SOUT` records and captured stderr as `SERR` records before continuing the batch. This bounds memory use and avoids blocking when a fixture writes more than a pipe buffer. The pinned FitNesse v20251025 implementation uses `SOUT.:` / `SERR.:` for the first record line and `SOUT :` / `SERR :` for continuation lines; this is reversed from the published protocol page. A single newline-only flushed message is omitted by the pinned logger. FitNesse strips the records and stores the two channels separately in the execution log. Output order within each captured descriptor is preserved, but stdout and stderr are spooled and forwarded independently, so exact cross-channel write order is not promised. See [`docs/slim-pipe-transport.md`](docs/slim-pipe-transport.md) for the version comparison and integration evidence.

`Fitnesse::Slim::Test::TestSlim::concatenate_three_args` joins its three script arguments with spaces, matching the upstream fixture used to exercise FitNesse's sequential-argument table syntax. Argument grouping remains FitNesse's responsibility; the fixture receives the resolved method arguments as usual.

`Fitnesse::Slim::Test::LoginDialogDriver` stores the expected username and password, counts every login attempt, and retains the upstream success/failure message. It returns SLiM boolean strings for accepted and rejected credentials.

`Fitnesse::Slim::Test::DetailedDiff` stores actual string, integer, double, and symbol values through the upstream setters, returns each through its matching `expected*` getter, and echoes a string. Its nested acceptance page uses FitNesse's own comparator and HTML diff rendering; the Perl fixture only supplies the state and values.

Fixtures implementing the upstream `StatementExecutorConsumer` contract receive their active executor through `set_statement_executor` after construction. They can set the reserved `SLIM_AGENT_FIXTURE_HANDLES_SYMBOLS` symbol to a regex of `instance.method` calls; only matching calls bypass ordinary symbol substitution. Setting the reserved symbol to null restores normal replacement. This is required for table fixtures that read and assign symbols inside one table, while keeping regular fixture calls unchanged.

`Fitnesse::Slim::Test::Statementexecutorconsumer::TableTableIncFirstCol` uses that hook to read symbol values in each input row, increment the first value, assign the result to the symbol named in the second cell, and return the upstream two-column result rows. It clears fixture-managed symbol mode even when a row fails. The acceptance page also checks symbol assignments before and after the table through the ordinary executor path.

`Fitnesse::Slim::Test::TableTableIncFirstCol` mirrors the ordinary upstream `fitnesse.slim.test.TableTableIncFirstCol` fixture. It has no mutable row state or executor hook: `do_table` increments the first cell as a Java signed integer and returns `['no change', 'pass:<value>']` in input order. The executor substitutes all table symbols before the call, and FitNesse applies symbols expressed in output cells after the complete result is returned. Therefore assignments from one row cannot affect another row's input. The distinct `Statementexecutorconsumer::TableTableIncFirstCol` remains responsible for fixture-managed, row-by-row symbol updates. More-specific package lookup keeps both fixtures addressable if an enclosing page also imports `fitnesse.slim.test`. The ordinary page passes 13/13 checks; the managed page continues to pass 15/15. This is fixture compatibility, not a new SLiM protocol feature. See [`docs/fitnesse-native-fixture-gap-triage.md`](docs/fitnesse-native-fixture-gap-triage.md) for the instruction trace and baseline review.

`Fitnesse::Slim::Test::DummyTableTableReturnsNull` mirrors the pinned Java fixture's no-argument construction and `doTable(rows)` contract: it returns Perl `undef` for the whole table. `StatementExecutor` and `Test::Slim::List` already serialize that result using SLiM's `null` value; no protocol or executor change is needed. FitNesse v20251025 interprets the null table result as `ignore(No results from table)`. This remains distinct from an empty string and an empty list. The Java and Perl target page results both report 1 right, 1 ignored, 0 wrong, and 0 exceptions. Instruction-level serialization and fixture-isolation coverage is in `t/null-table-fixture.t`.

`Test::Slim::ConverterRegistry` provides the small conversion contract needed by typed fixtures. Fixtures may expose `slim_method_signature($method)` with declared parameter and return type names; this explicit metadata avoids Java-style reflection and leaves unannotated fixture dispatch unchanged. Each `StatementExecutor` owns a registry, so converter changes are isolated to that SLiM connection. Arguments already supplied as references and null arguments pass through unchanged; scalar arguments use the declared type's `from_string` converter. Results use the declared converter, then the runtime-class converter as fallback. An exact `java.util.List` return that is already an array reference remains a nested SLiM list, while collection implementations such as `java.util.ArrayList` use the registered List converter. Collection elements are rendered recursively through runtime converters, and opaque references without a converter or explicit string method raise an exception instead of leaking a Perl address. Converter failures become SLiM exceptions with the invocation name. Standard String, boxed/primitive Boolean, Integer, Long, Double, Character, Date, void, and List converters are installed on reset. Numeric blank handling follows FitNesse: boxed numeric values become null, primitive numeric values become zero; Integer and Long enforce Java signed bounds. Double accepts decimal and exponent syntax. Perl represents Java Character values as integer UTF-16 code units (0..65535), so supplementary inputs map to their high surrogate and isolated surrogates remain representable; UTF-8 serialization replaces a lone surrogate with `?`, matching Java's default encoder replacement. Perl represents Java Date values as epoch milliseconds and parses/formats using the process local timezone and US `dd-MMM-yyyy` month names. Lenient day rollover is supported for years 1583..9999. Pre-1583 calendar cutover, out-of-range years, all `SimpleDateFormat` parser quirks, Java-specific non-decimal Double forms, dynamically inferred enum/array/collection converters, and JavaBeans property editors remain unsupported as implicit defaults. Fixtures can register, restore, or reset converters for those additional types.

`Fitnesse::Slim::Test::TestSlimWithConverter` mirrors upstream `TestSlimWithConverter`: its custom List converter changes collection string results from square to curly brackets and accepts both forms as a List argument. Its exact `List` getter continues to produce a nested SLiM list. Focused coverage is in `t/custom-converters.t`; the unchanged upstream `TestCustomConverter` page validates the observable dispatch and result behavior.

Fixture exceptions are formatted at the statement executor boundary. Ordinary fixture exceptions become SLiM exception results, preserving Java-style class names and messages where fixtures provide them. `ConstructorThrows` and `DecisionTableExecuteThrows` reproduce the upstream acceptance fixtures. Stop-test and stop-suite exceptions carry FitNesse's `ABORT_SLIM_TEST` or `ABORT_SLIM_SUITE` marker; `ListExecutor` then omits the remaining statements in that instruction batch and clears the stop request before the next batch. FitNesse consequently decides which later pages and teardown steps to run, while the Perl executor keeps ordinary exceptions non-stopping. These semantics are covered in `t/stop-exceptions.t` and the `StopSuite`, `StopTest`, and `StopTestInSuiteSetUp` acceptance pages.

`IgnoredTestsShouldColorGray` verifies that StopTest prevents later script calls and marks them ignored. Those stop/ignore checks pass, but two outer checks expect nested scenario cells with `class="ignore"`. The Perl HTTP PageDriver's nested request lacks the active FitNesse scenario context and renders the source as ordinary unexecuted script rows (`slimRowColor3`/`slimRowColor5` plus `<span class="ignore">Test not run</span>`). Java on the same FitNesse v20251025 JAR passes 7/0 and emits the expected scenario-cell markup. The previous explanation that these assertions were obsolete renderer expectations was wrong: the renderer can produce the expected markup in the Java nested context. This is another harness-context limitation, not a Perl ignore-marker or ResponseExaminer defect. Do not alter stop semantics or fabricate HTML.

The two `ErrorSituationsDuringSlimServerStartup` pages cannot exercise their intended startup failures through the shared acceptance harness configuration. `B_TimeoutAsSlimServerDiesBeforeConnecting` creates a nested page with an invalid `TEST_RUNNER` and expects FitNesse to report `Error SLiM server died before a connection could be established.` The active FitNesse process has `manually.start.test.runner=true`, so the nested request skips launching that runner and connects to the already-running Perl `SlimService` on 127.0.0.1:8099; its log reports `Connection to running SlimService`, exit 0, and zero seconds. `C_TimeoutAsNoServerAtGivenSocket` expects connection refusal at port 8099, but the external Perl service occupies that port, so its nested debug request also connects successfully. Both pages were run twice with identical outcomes: B has 2 right/1 wrong and C has 3 right/1 wrong; only each expected-error-text check fails. Their HTTP status and execution-log checks pass. These pages use PageDriver's nested HTTP requests and body checks directly; ResponseExaminer is not involved. The responsibility is shared harness/environment configuration, not Perl SLiM protocol behavior. A faithful run needs an isolated FitNesse context: run the outer suite against Perl on an alternate port, leave 8099 unbound for C, and allow B's nested request to use normal child-runner startup with its deliberately invalid runner. This requires independent startup properties and service ports; do not fake errors or alter page expectations to make the shared-server run pass.

Method results that are plain Perl hash references are converted at the statement-executor boundary by `Test::Slim::MapResult`, matching FitNesse's MapConverter HTML table representation. It sorts map keys for stable output, escapes ordinary cell text, retains valid HTML, and handles nulls and nested arrays/maps. This conversion is limited to map results; array references remain nested SLiM lists and other object references are not globally stringified. Object values inside a map require an explicit Perl string method, so opaque references cannot leak as `HASH(0x...)`. The behavior and identity preservation are covered by `t/hash-results.t`.

The transport-independent frame reader accepts colon-terminated six-or-more-digit byte lengths, including expanded lengths, and reads exactly the declared payload across partial system calls. `TEST_SLIM_MAX_FRAME_BYTES` defaults to 67,108,864 bytes (64 MiB) and can be set from 1 through 1,073,741,824 bytes. The list parser strictly decodes UTF-8 and measures item lengths in UTF-16 code units. Its defensive defaults are 128 nested lists, 1,000,000 decoded elements per message, and 16,777,216 UTF-16 units per item. The decimal frame prefix is limited to 32 digits, including leading zeroes. These are Perl resource policies, not FitNesse protocol limits. A complete request is parsed before its first statement runs; malformed serialized data closes only that client's connection or terminates only the pipe child, while a validly serialized malformed instruction returns `MALFORMED_INSTRUCTION` with its ID when available. FitNesse's invalid bracket-prefixed nested-list strings remain literal strings. The list parser uses a cursor and validates trailing data instead of repeatedly deleting prefixes. Regression tests cover 1,000,000-unit strings, a 1,000,000-byte frame, German, Estonian, Sindarin, BMP, supplementary, and combining text, strict malformed UTF-8, partial frames, and listener survival after rejected clients. Pipe process tests cover the v0.5 greeting, multiple frames, EOF, `bye`, and stdout isolation. See [`docs/slim-protocol-malformed-input.md`](docs/slim-protocol-malformed-input.md) for the complete policy and Java comparison. Fixture result conversion is declared explicitly through `slim_method_signature`: the standard registry emits FitNesse's `/__VOID__/` for declared void methods and lowercase text for boxed Boolean results. Undefined results from `callAndAssign` remain undefined in the executor's symbol store even though the wire response serializes them as `null`; exact symbol references preserve that value, while embedded null symbols interpolate as `null` text. A fixture exception does not bind a `callAndAssign` result. Ignore exceptions produce FitNesse's exact marker and stop the current instruction batch; the stop flag resets after that batch, leaving script/test scope filtering to FitNesse. Library instance names follow the protocol's `library` prefix, without requiring a numeric suffix. The conformance matrix in [`docs/slim-protocol-conformance.md`](docs/slim-protocol-conformance.md) records verified behavior and remaining Java-specific areas.

A nested `?test` starts another FitNesse-to-SLiM connection while the outer PageDriver call waits, so `Test::Slim::Server` accepts clients in the parent and forks one worker per connection. Each `process` call gets a fresh `ListExecutor`, which owns the session's actors, symbols, libraries, fixture instances, imports, and response context. The parent closes its copy of each accepted socket and reaps worker processes on `SIGCHLD`; malformed or disconnected clients close only their worker's socket and cannot reuse session state. Clean EOF at a message boundary ends a Perl session; EOF inside the prefix or payload is diagnosed and closes that client without a fabricated response. The pinned Java reader instead reports EOF as an I/O failure. This server model requires Perl `fork` support, which is available in the current Linux Codespaces and CI environments. Keep the HTTP client and response extraction in `t/lib/Fitnesse/Fixtures/`, outside `lib/Test/Slim/`.

# FitNesse acceptance runner

The 50-page inventory is a page-by-page external-Perl gate, not a proxy for FitNesse's complete native `SuiteSlimTests?suite` selection. FitNesse v20251025's native responder also considers empty Test properties, legacy wiki headers, prune directives, and referenced pages. Shared suite context can change nested-page outcomes, and some selected pages exercise Java fixtures or Java-only test-system behavior. The separate [`docs/fitnesse-native-suite-audit.md`](docs/fitnesse-native-suite-audit.md) records the exact selected paths, reconciled results, and backend evidence. Do not replace the stable 50-page gate with native suite totals until a scoped inventory establishes applicability and backend attribution.

`bin/perl-slim` accepts FitNesse runner arguments `-v` (verbose request/response diagnostics on stderr) and `-s <seconds>` (per-statement fixture timeout), followed by a port. Port `1` selects pipe transport; other valid ports start the TCP listener. Unknown or malformed options fail with usage text. Both transports share the executor and timeout behavior. FitNesse v20251025 forwards page-level `SLIM_FLAGS` to child processes; an externally managed TCP listener does not receive those child arguments.

`bin/test-fitnesse` selects a transport with `--transport pipe|tcp` (pipe is the default). Both modes extract the pinned upstream wiki into an isolated temporary root, run a bounded isolated FitNesse HTTP service, clear generated `MySuite` state before each request, and compare exact per-page tuples as well as conformance. Pipe mode sets temporary root runner defaults so nested PageDriver requests use the Perl child, and confirms the command and child exit status from execution logs. TCP mode starts and probes a Perl listener and verifies the external connection. `END` cleanup reaps owned processes while preserving the runner's status. Both modes have exact page-by-page expectations; a small number of startup pages differ because one launches a child while the other connects to an external socket. See [`docs/fitnesse-acceptance-pipe-migration.md`](docs/fitnesse-acceptance-pipe-migration.md).

The broader native `?suite` check is a separate gate in `bin/test-fitnesse-suite` with the same transport selector and isolated wiki. It compares the exact inventory and all four counts page by page, and attributes TCP sessions through listener request/response traces or pipe sessions through exact child commands and exit statuses. Its committed baseline remains the audited TCP baseline; the observed pipe deltas are recorded separately and have not been approved as baseline updates. A matching result is a no-regression result for that mode, not complete conformance. Persistent XML, JSON, and service logs remain under ignored `.runtime/` for diagnosis.
