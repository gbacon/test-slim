# Current design

`Test::Slim` has three small execution layers. `Test::Slim::Server` reads and writes framed SLiM messages over a socket. `Test::Slim::List` handles SLiM list values and lengths, including recursive nested statements and zero-length string items. `Test::Slim::ListExecutor` turns each decoded statement into a `Test::Slim::Statement` call.

`Test::Slim::Statement` routes protocol operations to `Test::Slim::StatementExecutor`. The statement executor owns imported class prefixes, actor instances, registered library instances, and symbols. It resolves graceful class and method names, constructs fixtures, substitutes symbols, converts HTML table arguments where appropriate, dispatches actor methods before searching libraries newest-first, and formats results or SLiM exceptions. A call to FitNesse's `cloneSymbol` helper uses the reserved `null` target and returns the resolved symbol value unchanged, preserving object identity. If a scenario call names an actor that has no instance, dispatch searches registered libraries newest-first before reporting an error.

Perl tests use fixtures under `t/lib/`. The `Eg::Division` fixture mirrors FitNesse's `eg.Division` example: it stores numerator and denominator state, exposes setters, and returns a Java-compatible double quotient. `Fitnesse::Slim::Test::ShouldIBuyMilk` mirrors the upstream decision-table fixture, including its stateful milk/cash/card decision and optional no-op table hooks. FitNesse acceptance pages live in the locally installed wiki tree (ignored by Git) and connect through the Perl server on port 8099. The acceptance inventory and the current observed failure groups are recorded in [`docs/fitnesse-slim-acceptance-baseline.md`](docs/fitnesse-slim-acceptance-baseline.md).

`PageDriver` and `ResponseExaminer` are acceptance-test harness fixtures, not protocol components. Upstream PageDriver creates pages and runs FitNesse requests using FitNesse's in-process wiki/request context; ResponseExaminer reads the resulting response and page HTML from that context. The Perl PageDriver in `t/lib/Fitnesse/Fixtures/PageDriver.pm` makes the equivalent FitNesse `saveData` and `saveProperties` requests over HTTP, runs page/test/suite/log responders, and retains each response's status and body. Its acceptance-used `content`, `contentContains`, `contentMatches`, and `lineNumberContaining` methods inspect that body. `Fitnesse::Fixtures::ResponseContext` exposes the most recent HTTP response to other harness fixtures in the same worker process. `ResponseExaminer` in `t/lib/Fitnesse/Fixtures/ResponseExaminer.pm` reads this shared status and body, supports the upstream `contents`, `rawContents`, `fullContents`, `pageContents`, `pageHtml`, and `status` selectors, and performs Java-style multiline/dotall regex extraction through `found` and `extractMatch`. It also exposes the upstream line and match-count helpers needed by fixtures; it introduces no HTTP client or protocol state.

The test fixtures `Fitnesse::Fixtures::SplitFixture` and `Fitnesse::Fixtures::DuplicateRows` mirror the installed FitNesse v20251025 query fixtures. Both take one string constructor argument and expose `query()`, returning nested row lists whose entries are column/value pairs. SplitFixture splits semicolon-separated rows and comma-separated cells and labels columns with one-based string keys. DuplicateRows returns the upstream phase A/B order and retains duplicate values. The query tests also use the protocol 0.4 `assign` instruction, which stores a symbol value (including null) and returns `OK`; the server advertises `Slim -- V0.4` accordingly. These fixture implementations remain under `t/lib/Fitnesse/Fixtures/`, outside the core executor.

A nested `?test` starts another FitNesse-to-SLiM connection while the outer PageDriver call waits, so `Test::Slim::Server` accepts clients in the parent and forks one worker per connection. Each `process` call gets a fresh `ListExecutor`, which owns the session's actors, symbols, libraries, fixture instances, imports, and response context. The parent closes its copy of each accepted socket and reaps worker processes on `SIGCHLD`; a malformed or disconnected client closes only its worker's socket. This server model requires Perl `fork` support, which is available in the current Linux Codespaces and CI environments. Keep the HTTP client and response extraction in `t/lib/Fitnesse/Fixtures/`, outside `lib/Test/Slim/`.
